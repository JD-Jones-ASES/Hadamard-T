## 2. Definitions

All arithmetic below is over the integers; no floating point occurs anywhere in
this repository.

**Hadamard matrix.** An `n × n` matrix `H` with entries in `{+1, −1}` such that
`H Hᵀ = n·I_n`. Equivalently, every pair of distinct rows is orthogonal.

**Circulant.** For `x ∈ ℤⁿ`, `circ(x)[i][j] = x[(j − i) mod n]`. A circulant is
determined by its first row.

**Periodic and non-periodic autocorrelation.** For `x` of length `n`,

```
PAF(x)(s)  = Σ_{q ∈ Z_n} x[q]·x[(q + s) mod n]           (periodic)
NPAF(x)(s) = Σ_{q=0}^{n-1-s} x[q]·x[q + s]               (non-periodic)
```

**T-matrix quadruple of order `n`** (the Cooper–Wallis input). Four circulant
matrices `T₁, …, T₄` of order `n` with entries in `{0, +1, −1}` whose first rows
have pairwise disjoint supports partitioning `Z_n` — exactly one `Tᵢ` is nonzero
at each position — satisfying the **periodic** identity

```
Σᵢ Tᵢ Tᵢᵀ = n·I_n      ⟺      Σᵢ PAF(Tᵢ)(s) = n·δ₀(s)
```

where `δ₀(s) = 1` if `s = 0` and `0` otherwise. This is the axiom, and it is a
periodic one.

**T-sequences of length `n`.** The same disjointness, with the aggregate
**non-periodic** autocorrelation vanishing at every nonzero lag. T-sequences of
length `n` give T-matrices of order `n` by taking them as first rows; the
converse does not hold.

**NPAF guard.** The order-103 object of section 4 satisfies the periodic
identity only. Its aggregate non-periodic autocorrelation is nonzero at 94 of
the 102 positive lags, so it is a T-matrix quadruple and **not** a T-sequence
quadruple. Whether aperiodic T-sequences of length 103 exist is open; nothing
in this repository closes it, and no such claim is made anywhere here.

**Williamson quadruple of order `w`.** Four symmetric circulant `±1` matrices
`A, B, C, D` of order `w` with

```
A² + B² + C² + D² = A Aᵀ + B Bᵀ + C Cᵀ + D Dᵀ = 4w·I_w
```

equivalently `Σ PAF(row)(s) = 4w·δ₀(s)` over the four first rows.

**Goethals–Seidel array.** For four `±1` matrices `X₁, …, X₄` of order `v` and
`R` the back-identity of order `v` (`R[i][j] = 1` iff `i + j = v − 1`), the
`4v × 4v` block matrix

```
[   X₁      X₂R     X₃R     X₄R  ]
[ −X₂R      X₁    −X₄ᵀR    X₃ᵀR  ]
[ −X₃R    X₄ᵀR      X₁    −X₂ᵀR  ]
[ −X₄R   −X₃ᵀR    X₂ᵀR      X₁   ]
```

is Hadamard of order `4v` whenever `Σⱼ Xⱼ Xⱼᵀ = 4v·I_v` and each `Xⱼ` satisfies
`Xⱼᵀ R = R Xⱼ` (type 1 with respect to `R`), which holds when `Xⱼ` is developed
over an abelian group.

**The Cooper–Wallis composite.** T-matrices of order `n` together with four `±1`
matrices of order `w` that pairwise satisfy `M Nᵀ = N Mᵀ` and `Σ M Mᵀ = 4w·I`
give a Hadamard matrix of order `4nw`. Symmetric circulants satisfy the pairwise
condition, so a Williamson quadruple of order `w` is admissible. Concretely,
with `⊗` the Kronecker product and the index on `Z_n × Z_w` lexicographic,

```
X₁ =  T₁⊗A + T₂⊗B + T₃⊗C + T₄⊗D
X₂ = −T₁⊗B + T₂⊗A + T₃⊗D − T₄⊗C
X₃ = −T₁⊗C − T₂⊗D + T₃⊗A + T₄⊗B
X₄ = −T₁⊗D + T₂⊗C − T₃⊗B + T₄⊗A
```

Every entry is `±1` because exactly one `Tᵢ` is nonzero at each position. Each
column of the sign table is a permutation of `{A, B, C, D}`, so the diagonal
coefficient of `Σⱼ Xⱼ Xⱼᵀ` is `A² + B² + C² + D² = 4w·I_w`; each off-diagonal
coefficient telescopes to zero because symmetric circulants commute. Hence
`Σⱼ Xⱼ Xⱼᵀ = (Σᵢ Tᵢ Tᵢᵀ) ⊗ 4w·I_w = 4nw·I_{nw}`, and `R = R_n ⊗ R_w` is the
back-identity of order `nw`, so the Goethals–Seidel array applies.

The shared assembler for this construction is `tools/assemble.py`. It is a
**finder**: nothing it produces is accepted on its own word. The sole acceptor
is `verify/verify.py`.

**Proposition 1 (the multiplier tier, and why 105 is the size of the problem).**
*Let `V = 515 = 5 · 103` and let `⟨149⟩ ≤ U(Z₅₁₅)` be the tier of Theorem A.*

1. *`gcd(5, 103) = 1`, so `Z₅₁₅ ≅ Z₅ × Z₁₀₃` by the Chinese remainder theorem.*
2. *`149` has order 6 in `U(Z₅₁₅)`: its powers are `149, 56, 104, 46, 159, 1`,
   so `⟨149⟩ = {1, 46, 56, 104, 149, 159}`.*
3. *Under the split, `149 ↦ (−1, 46)` — order 2 on the `Z₅` factor, order 3 on
   the `Z₁₀₃` factor — and `104 = 149³ ↦ (−1, 1)` is the unique element of order
   2 in the tier. So `x ↦ 104x` negates the `Z₅` coordinate and fixes the
   `Z₁₀₃` coordinate: an involution of `Z₅₁₅` with 103 fixed points. The tier
   factors as `⟨−1⟩ × ⟨46⟩` across the two legs, of order `2 · 3 = 6`.*
4. *`⟨149⟩` acting on `Z₅₁₅` by multiplication has*

   ```
   1 + 4/2 + 102/3 + (4·102)/6 = 1 + 2 + 34 + 68 = 105
   ```

   *orbits: one fixed point, 2 of size 2, 34 of size 3, 68 of size 6, and
   `1·1 + 2·2 + 34·3 + 68·6 = 515`. The four summands are the four CRT strata,
   and the tier acts freely on the last of them.*
5. *Hence a `⟨149⟩`-invariant `±1` sequence on `Z₅₁₅` is one sign per orbit:
   `2¹⁰⁵` of them, and `2⁴²⁰` invariant quadruples, against `2⁵¹⁵` and `2²⁰⁶⁰`
   unrestricted.*

Nothing in Proposition 1 is claimed as new: parts 1–4 are elementary CRT and
orbit counting, and any competent reader re-derives them in a page. What is
asserted is that these particular numbers for this particular tier are exactly
right and machine-checked. The group and the invariance are re-derived by
closure in `certs/01-h2060-artifact/run.py`; the orbit arithmetic is displayed
above in full.

Proposition 1 is what makes the decode legible. The `×104` twist changes only
the sign of the `Z₅` coordinate and leaves the index function mod 103 alone,
which is why the plain and twisted expansions of one seed differ so little; and
105, not 515, is the number of free signs the symmetry ansatz leaves. Everything
downstream — the order-103 readout, the assembly template — is bookkeeping on
top of that count.

   `(0, ±1)` circulants — is neither symmetric nor amicable in any pair, and
   yields `H(412)` and nothing above it.
2. Every published route to a T-object at 103 fails on arithmetic. Base
   sequences would need `BS(52, 51)`, past the verified frontier at `n ≤ 43`;
   the Turyn-type ladder gives lengths `3n − 1` and steps over 103; Turyn
   sequences give `4l − 1` with only a few known examples, all short; and 103 is
   prime, so every multiplication route needs a factorisation it does not have.
3. A status line in a survey is not recoverable data. The relevant one is
   overbroad as written, and its own source lineage is documented as unreliable
   in exactly this way. Label for any such line:
   **REPORTED-FROM-AUDITED-TABLE** (source, edition, retrieval date). Đoković

   not accurate even at the time of its publication".
4. The field's own frontier corroborates the audit, and no more than that.
   `T(103) × W(5) ⟹ H(2060)` in one multiplication, and 2060 was the smallest
   order with no publicly known Hadamard matrix until 2026-08-23. Any earlier
   publicly accessible and recoverable order-103 T-matrix would, through that
   classical product, have supplied a construction of H(2060) at once; the
   longstanding gap is therefore strong corroborating evidence, not a proof of
   absence — a published object can be overlooked, misclassified, or never
   propagated. The earliest publicly accessible instance the audit located is
   the one implicit in the gist, which is exactly where this object came from.

**What this repository adds at order 103**, therefore: the decode of
the public artifact, the identification of the object as a T-matrix quadruple

products of section 5. Not the object.

prime-order objects are explicit one-off cyclotomic constructions at 73, 79

content is bounded by the book's own appendix. Objects in this subfield have
also appeared on public posting sites repeatedly during 2026. Any dated

### 6.3 Order 131 — twice, and the two are different objects

**The literature route.** London–Kotsireas 2025 construct Turyn-type sequences
`TT(44)`, and the classical chain `TT(44) → BS(87, 44) → TS(131)` closes order
131. Both arrows are re-derived inside `certs/05-t131-products/run.py` rather
than quoted. Arrow 1: if `(A, B, C, D)` are Turyn-type of lengths `n, n, n, n−1`
then `(C;D, C;−D, A, B)` are base sequences of lengths `2n−1, 2n−1, n, n`,
because the cross terms of the two concatenations cancel identically. Arrow 2:
from base sequences `(P, Q, X, Y)` of lengths `m, m, n, n`,

```
T₁ = (P+Q)/2 ; 0_n      T₂ = (P−Q)/2 ; 0_n
T₃ = 0_m ; (X+Y)/2      T₄ = 0_m ; (X−Y)/2
```

are `(0, ±1)` with disjoint supports covering `Z_{m+n}`, and their aggregate
autocorrelation is half that of the base sequences. The resulting object is a
true T-sequence quadruple: its aggregate non-periodic autocorrelation is
`131·δ₀`.

The `TT(44)` payload is credited to London–Kotsireas 2025. Its status here is
**VERIFIED-PRIMARY**: the paper was read firsthand from the publisher PDF, all
three of its printed hexadecimal payloads are byte-identical to the ones banked
here, and the decoding convention this laboratory first detected by search is
the paper's own printed formula — its published decoding procedure, transcribed
once, round-trips every payload. The paper also prints its own T(131), as a
figure, decoded here by glyph segmentation; that object is identical in all 524
symbols to the one obtained here by the chain above. One object, two
derivations; the one here is replayable from this repository.

**Corollary G.** *Through the same composite with Williamson quadruples of
orders 7, 11, 13, 17, 19, the literature-route quadruple gives explicit
Hadamard matrices of orders 3668, 5764, 6812, 8908 and 9956.*

The five orders are listed unresolved in Table 4 v2, but a **published route
closes them**, and this laboratory claims no novelty of existence at any of
them. What is claimed is narrower: the first publicly accessible and
independently reproducible construction of `H(3668)`, `H(5764)`, `H(6812)`,
`H(8908)` and `H(9956)` located in our audit of 2026-08-29 — explicit matrices,
rebuildable by anyone from this repository, with a trust chain that is 250 lines
of standard-library Python. The five orders are recorded because they had not
been written down, and the credit for the object that unlocks them belongs to
London and Kotsireas.

**Theorem F (a second, independent witness).** *There is a T-matrix quadruple
of order 131 with support profile `(11, 10, 55, 55)`, row sums `(−9, 0, 5, 5)`,
and strict multiplier group of order 5 — the witness this repository banks and
replays.* Label: **PROVEN-BY-CERTIFICATE**, in `certs/05-t131-products/run.py`.

The witness came from a pre-registered search over the unique order-5 subgroup
of `Z₁₃₁*` — 27 orbits, 81 cells, 13 reduced equations, with the admissible
row-sum profile computed to be unique up to per-class sign flip before any
search ran. The search record — sixteen matches over four canonical masks,
eight distinct unordered quadruples, zero recheck failures, spanning support
profiles `(11, 10, 55, 55)` (twelve of the sixteen) and
`(11, 10, 45, 65)` / `(11, 10, 65, 45)` (the other four) — is
COMPUTATIONAL-EVIDENCE, banked in `data/T131-multiplier-tier.json` and not
replayed by the certificate, which checks the selected witness alone.

**Proposition 3 (inequivalence, by invariant separation).** *The two witnesses
are not equivalent. Their support multisets are `(44, 43, 23, 21)` and
`(11, 10, 55, 55)`, and the support multiset is preserved by every equivalence
move on T-matrix quadruples — reordering, negation, shift and decimation each
permute or translate the four supports without changing their sizes. The
separation of this one invariant is a certified inequivalence, obtained
without an orbit search.*

The two representatives banked here also differ in row sums, in strict
multiplier-group order (1 against 5), and in aggregate non-periodic
autocorrelation (`131·δ₀` against nonzero off-peak). Those are recorded as
descriptions of the banked representatives, not used as invariants: the strict
stabiliser and the non-periodic autocorrelation are not preserved under cyclic
shift — shifting the second witness by one position keeps it an equivalent
T-matrix quadruple and collapses its strict stabiliser to the identity — so
nothing in the inequivalence argument rests on them.

Label: **PROVEN-BY-CERTIFICATE**, computed in `certs/05-t131-products/run.py`.
Because the two are different objects, each of the five orders is built twice,
from independent inputs, and the ten resulting matrices come in five pairs with
distinct canonical digests; the certificate asserts each inequality.

The second witness has a second use. It is a **positive control for the search
class**: the engine, calibrated in advance against exhaustive brute force at
small parameters and against the certified exhaustion at order 163, found an
object of the target kind at order 131 inside its first completed expensive
stratum. That is a fact about the tier, not a closure of it.

### 6.4 The honest gate — what the search class does not do

A cost verdict is never an emptiness verdict. Full exhaustion of the order-5
tier at 131 costs 1.73628 × 10¹⁴ half-elements, 6.678 × 10¹² after the rotation
quotient, roughly fourteen days single-worker. It is **PRICED OUT**. The
registered run took four cheap strata whole and sampled the bulk, and stopped at
its registered budget; a partial run is not nonexistence, and the sampled strata
close nothing. The tiers at `d = 1` and `d = 2` at 131 (`2³⁹³` and `2¹⁹⁸`) are
untouched. Six of the eight divisors of 130 were shown Diophantine-dead before
the search — no profile even solves `Σ rᵢ² = 131` — which is a proof, and the
remaining cost is a price.

The same discipline applies elsewhere. At 163 the exhaustion of the order-9
tier is search history (section 6.1), recorded and not replayed —
`certs/03-t163-products` replays the witness and its products — and nothing is
said about the tiers at `d = 3, 2, 1`, which were never searched. `certs/04-t-bank` certifies a negative — those three
quadruples cash in nothing — within Cooper–Wallis and within Table 4's range,
and nothing outside it. No certificate in this repository covers order 151, and
no statement about order 151 is made here.

## 7. Verification

### The trust chain

`verify/verify.py` is the sole acceptor. It is standard library only, exact
integer arithmetic only, and it shares no code with anything that builds a
matrix. Rows are packed into Python integers; the inner product of two `±1` rows
of length `n` is `n − 2·popcount(xor)`, so orthogonality of a pair is exactly
`popcount(xor) == n/2`. There is no floating point anywhere in it. It reports

```
VERDICT: HADAMARD order=<n> all <k> row pairs orthogonal canonical_sha256=<hex>
```

on success and exits 0; it exits 1 on a matrix that fails and 2 on a parse
error. The canonical digest is the SHA-256 of the `'+'`/`'-'` serialization, one
row per line, which is the same form the banked artifact is stored in.

Run its self-test first. It builds Sylvester matrices, accepts them, and must
reject a battery of near-misses and malformed inputs:

```
python verify/verify.py --selftest
```

Everything a certificate builds is written to a temporary file, handed to
`verify/verify.py` in a subprocess, and deleted. Nothing large is committed. The
digests below are what bind the large matrices, and each is pinned three ways
inside its certificate: the certificate's own streaming digest, the verifier's
verdict field, and a constant in the certificate's source.

### Honesty labels

Used throughout this note with fixed meanings.

- **PROVEN-BY-CERTIFICATE** — a finite exact computation replayed by a
  certificate here, with `verify/verify.py` the sole acceptor of any matrix.
- **VERIFIED-PRIMARY** — checked against the primary source, read firsthand.
- **REPORTED-FROM-AUDITED-TABLE** — quoted from an external table with source,
  edition and retrieval date. A table records what its authors knew, not what
  exists.
- **REPORTED-FROM-SECONDARY-SOURCE** — reached through a machine-mediated
  source. Everything so labelled during this work has since been upgraded to
  VERIFIED-PRIMARY.
- **COMPUTATIONAL-EVIDENCE** — measured, corroborating, not proof.
- **PRICED OUT** — a cost verdict on a search. Never a statement of emptiness.
- **NOT CLAIMED** — stated so that its absence is not mistaken for an oversight.
